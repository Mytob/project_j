# Version 1.2 scope and design

This document records the authorized v1.2 handoff. It supplements the frozen
v1.0 decisions and the specifically authorized v1.1 TOTP requirements; it does
not rewrite their history. Scope is limited to the administrator interface
redesign and the VPS and Jellyfin reverse-proxy statistics described here.

## Administrator interface

Redesign the existing Go server-rendered administrator pages using the approved
Statistics screenshot as a visual reference: charcoal background, lighter
rounded cards, restrained teal highlights, compact metrics, graphs, a left
navigation rail, clear status and responsive layouts. Keep JavaScript minimal
and do not add a frontend framework or build pipeline.

Navigation may link only to implemented functionality. Preserve login,
whitelist management, TOTP setup and disable, and authenticated WireGuard
configuration download. Add a Statistics page. Existing management controls
must remain protected by the same sessions and CSRF checks. Do not add
placeholder WireGuard, TLS, website, update, audit, or general settings pages.

## VPS host collector

Add an unprivileged Go collector container to the existing Compose stack. It
must sample the actual Linux host, not its container, for CPU, RAM, swap, root
filesystem capacity, host network receive/transmit rates and totals, load
averages, and uptime. It has no published port, Docker socket, added Linux
capabilities, host PID namespace, or host network namespace. Use read-only host
metric mounts and document the minimum visibility required. Host network
counters must exclude loopback and virtual Docker interfaces and must not
double-count traffic.

Monitoring failure must not stop the proxy. Unavailable measurements are
represented as unavailable, never fabricated as zero. Container permission
and isolation claims require container tests.

## Proxy instrumentation

Collect only traffic served by `access.<base-domain>`: active HTTP requests,
request rate, allowed and allowlist-blocked requests, HTTP errors, error rate,
incoming/outgoing bytes per second, and total bytes. Incoming means bytes
received by the proxy from clients; outgoing means bytes sent by the proxy to
clients. These are HTTP allowlist decisions, not VPS firewall packet drops.

Instrument bytes while response and request bodies are in flight without
buffering media. Preserve range requests, WebSockets, streaming, interrupted
transfers, and normal operation if metrics collection fails. Do not call the
Jellyfin API or record playback, media, user, client-IP, or URL history. No
firewall-drop, playback-session, or viewer claims are permitted.

## Delivery and persistence

The authenticated Go administrator backend streams current metrics to signed-in
browsers over SSE, targeting one-second updates. The collector and metric
transport have no public endpoint. SSE must validate the existing administrator
session, stop at expiry/revocation, reconnect cleanly, and bound queues and
per-client work. Background tabs should not cause unbounded work.

Persist bounded, compact file-based aggregates for 90 days, using the existing
data directory so history survives container restarts and normal updates. Use
atomic writes, validate input on recovery, tolerate counter resets and process
restarts, aggregate longer ranges, and expire old data automatically. No
database, Prometheus, Grafana, or new monitoring service is in scope.

Supported ranges are 24 hours, 7 days, 30 days, and 90 days. Historical graphs
must use aggregated data for longer ranges. Show only measurements present in
the data; do not invent filesystem classifications or demonstration values.

## Deployment and security

The collector participates in install, configuration, startup, restart,
update, rollback, and applicable uninstall flows. Bundle/pin its image under
the existing release strategy. Preserve history through update and rollback.
Keep the active and previous known-good releases and never globally prune
unrelated Docker images. Do not install a host monitoring daemon. Production
target remains Ubuntu 26.04 LTS x64. Do not deploy to the production VPS without
separate explicit approval.

Preserve default-deny IPv4/IPv6/CIDR access control, trusted socket peer address
semantics, administrator password/session/CSRF protections, TOTP and CLI-only
recovery, and private Caddy administration. Fail closed on access-control
configuration errors. Statistics are private administrator data and must not
leak through public endpoints or logs.

## Required automated verification

The v1.2 local gate runs on Windows 11 x64 with WSL2 and Docker. It extends the
existing release gate and includes real collector host counters and permission
tests; reset and wrap handling; collector restart/failure recovery; streaming,
long response, cancellation, concurrent, range, WebSocket, IPv4/IPv6, allow,
deny, errors and byte counting against actual local components; authenticated
SSE, reconnection and session expiry; 90-day aggregation, retention, restart,
upgrade, rollback and corrupt-data recovery; and browser automation of existing
admin journeys, navigation, charts, responsive layouts, keyboard operation,
and empty/error/disconnected states. Existing v1.0/v1.1 release checks remain
mandatory.

Do not push or open a PR unless every mandatory local check executes and passes.
If Windows/WSL2/Docker capability is unavailable, record the exact blocker and
keep changes local. Record only commands actually run and observed results in
`docs/ROADMAP.md` and `docs/TESTING.md`.

## Acceptance

Complete only when the redesigned admin retains all implemented workflows;
host measurements reflect the host; in-flight proxy bytes are measured
accurately; authenticated SSE updates live values; 90-day history survives
restart/update and is safely bounded; all endpoints and data remain private;
installer, updater, rollback and package flows preserve data; documentation is
current; and every mandatory automated gate passes.
