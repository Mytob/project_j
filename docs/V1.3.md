# Version 1.3 scope and implementation record

This document records the user-authorized v1.3 brief supplied on 2026-10-15.
The screenshot attached to that request is the visual reference: near-black and
deep blue surfaces, cool cyan accents, refined borders, subtle illumination,
clear charts, and a compact infrastructure-management layout. Its example
widgets are not requirements unless they represent product data already
available in Jellyfin Proxy.

## Approved scope

- Migrate the administrator UI to React, TypeScript, and Vite, with static
  assets embedded in the Go application. Node is build/test-only and must not
  be present as a production VPS runtime.
- Preserve password and TOTP authentication, CSRF, private authenticated
  statistics/SSE, allowlist default-deny, Caddy's private admin socket,
  collector isolation, and bounded 90-day statistics history.
- Provide responsive Dashboard, Statistics, Health, Access Control,
  WireGuard, and Security experiences for mobile and desktop.
- Add evidence-based component diagnostics, password changes, and safe
  WireGuard peer rotation and configuration delivery/deletion.
- Audit and update dependencies using exact stable versions, lockfiles,
  upstream image digests, and recorded security-check evidence.
- Keep all required release gates local to Windows 11 x64, WSL2, and Docker.
  Continue using feature branches and PRs into `dev`; do not deploy to the
  production VPS without separate explicit authorization.

## Architecture constraints

The existing no-framework rule from v1.2 is superseded only for this approved
v1.3 React migration. Node remains a build-time tool. Production serves one
self-contained Go application with static frontend assets and existing private
backend APIs. No Docker socket, privileged admin container, host namespace,
public management endpoint, database, additional media service, or hosted CI
is authorized.

Health must not claim container liveness without an authorized observation
path. Checks unavailable under the isolation boundary must report Unknown and
explain why. A WireGuard interface heartbeat alone does not prove the Windows
peer or Jellyfin endpoint is reachable. Each Healthy/Degraded/Down state must
be tied to a fresh, documented signal. The observable path is Caddy →
WireGuard → Windows endpoint → Jellyfin.

Password changes must verify the existing password and CSRF token, apply the
existing password hash policy, rate-limit attempts, persist atomically, retain
TOTP state, and revoke all active sessions. The root-only `proxyctl
reset-password` recovery remains supported.

WireGuard rotation must install the new public peer and revoke the old peer
with rollback on failure. Client private configuration must be access
controlled and removed after a successful server-side download transfer;
interrupted delivery must remain recoverable. The UI must say the browser
received a download response, not claim that a file was saved. Removing a
downloadable file and revoking a peer are distinct actions. Deleted private
keys must not enter logs, temporary backups, or release artifacts.
